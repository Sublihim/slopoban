# Slopoban · СКЛАД-БОТ

Браузерный Sokoban в ретро-стиле приставок 90-х. Ванильный JS/CSS, без
библиотек и сборки. Работает открытием `index.html` прямо с диска (file://)
и как **Telegram Mini App** — одним и тем же кодом.

## Запуск
Открыть `index.html` в любом современном браузере. Сервер не нужен
(генерация уровня в этом режиме идёт в UI-потоке — воркеры на `file://`
запрещены). Для полноценного режима достаточно любой раздачи статики:
`npx serve .` или `python -m http.server`.

Единственный внешний запрос — SDK Telegram с `telegram.org`. Без сети он
просто не загрузится: `js/tg.js` это переживает и уходит в браузерный
фолбэк, игра работает как обычно.

## Правила
- Дотолкай все ящики до зелёных меток на складе.
- **Пешие шаги не ограничены** — лимитированы только **шаги с грузом**
  (толчки): лимит = оптимум + 10.
- Толкнул ящик в безвыходное место (мёртвый угол, замороженный блок) —
  уровень провален сразу.
- Провал уровня: **−1 жизнь**, та же раскладка заново. Победа: **+1 жизнь**
  (максимум 9). Старт: 3 жизни. 0 жизней — игра окончена.
- 100 уровней; размеры полей, число ящиков (3–6) и раскладки целей
  варьируются от уровня к уровню.

## Управление
- Стрелки / WASD — движение
- Свайп по полю — ход в направлении свайпа (мобильные)
- **Z** — отменить ход (счётчики откатываются)
- **R** — перезапустить уровень (с подтверждением, стоит жизнь)
- Экранная крестовина — на экранах уже 900 px (на десктопе скрыта)
- В Telegram: «Назад» — перезапуск уровня, главное действие оверлея
  продублировано в нативную кнопку внизу

## Генерация уровней
Каждый уровень собирается на лету и **доказуемо проходим**:

1. **Параметры** — случайный класс размера поля (малый 13×9 … большой
   27×17), 3–6 ящиков, схема раскладки целей; веса плавно смещаются
   с ростом номера уровня, но разнообразие сохраняется всю кампанию.
2. **Планировка** — комнаты неправильной формы, соединённые узкими
   коридорами, плюс колонны; снаружи — пустота (стиль старых DOS-игр
   типа «Мудрого Крота»).
3. **Цели** — одна из четырёх схем: кластер-«склад» в комнате, две
   группы в разных комнатах, линия-«полка» или разброс по всему полю.
4. **Обратный ход** — ящики ставятся на цели и «вытягиваются» по лабиринту
   направленными протяжками (выбирается протяжка с максимальным приростом
   расстояния до целей), пока нижняя граница сложности не достигнута.
   Ящик **никогда** не остаётся на цели и не попадает в мёртвую клетку.
5. **Проверка** — push-решатель (A* по толчкам с допустимой эвристикой
   Σ dist(ящик→цель)) подтверждает: оптимум решения в пределах
   **9–20 шагов с грузом** (нижняя граница растёт с номером уровня:
   9 → 17). Слишком простые и слишком длинные позиции отбраковываются
   ещё до решателя по нижней границе Σdist. Если планировка упорно не
   даёт годную позицию, планка сложности временно снижается (вплоть до
   6 толчков) — уровень обязан появиться.

Поле — до 40×40 (реально 13×9 … 27×17), ящиков 3–6.

## Telegram Mini App

Игра запускается как мини-апп без бэкенда: весь код клиентский, сервер
нужен только чтобы отдать статику по HTTPS.

### Развёртывание
1. Выложить папку на любой HTTPS-хостинг (nginx/Caddy за Traefik, GitHub
   Pages — см. ниже, Cloudflare Pages). Валидный сертификат обязателен.
2. В [@BotFather](https://t.me/BotFather): `/newbot` → `/newapp`, указать
   URL. Либо `/setmenubutton` — кнопка меню бота с тем же URL.
3. Открыть по прямой ссылке `t.me/<bot>/<app>` или через кнопку меню.

Ничего больше не требуется: ни вебхуков, ни валидации `initData` —
игра не отправляет на сервер ни байта.

## GitHub Pages

В репозитории лежит `.github/workflows/pages.yml`: на каждый пуш в `master`
содержимое репозитория публикуется на Pages как есть — сборки нет.

Репозиторий называется `slopoban` — именно его имя становится путём
сайта, поэтому переименование репозитория меняет и URL мини-аппа.

```
git remote add origin https://github.com/<user>/slopoban.git
git push -u origin master
```

Включить один раз: **Settings → Pages → Build and deployment → Source:
GitHub Actions**. После первого прогона сайт доступен по адресу
`https://<user>.github.io/slopoban/` — этот URL и скармливается BotFather.

Особенности:
- Сайт живёт в подкаталоге (`/slopoban/`), поэтому все пути в проекте
  относительные; воркер `js/gen-worker.js` тоже резолвится относительно
  страницы. Проверено при раздаче из подкаталога — 404 нет.
- `.nojekyll` отключает обработку Jekyll: файлы отдаются один в один.
- Приватный репозиторий публикует Pages только на платных тарифах;
  для публичного ограничений нет.
- Свой домен — **Settings → Pages → Custom domain**; тогда сайт лежит
  в корне и URL для BotFather меняется на него.

### Что даёт интеграция
| Возможность | Реализация | Мин. Bot API |
|---|---|---|
| Полная высота окна, корректный размер поля | `expand()`, `viewportStableHeight` | 6.1 |
| Свайпы по полю не сворачивают приложение | `disableVerticalSwipes()` | 7.7 |
| Прогресс кампании в облаке Telegram | `CloudStorage` | 6.9 |
| Отдача на толчок, победу и провал | `HapticFeedback` | 6.1 |
| Главное действие оверлея нативной кнопкой | `MainButton` | 6.0 |
| «Назад» = перезапуск уровня / отмена диалога | `BackButton` | 6.1 |
| Отступы под чёлку и шапку клиента | `safeAreaInset`, `contentSafeAreaInset` | 8.0 |
| Шапка и фон клиента в палитре игры | `setHeaderColor` и др. | 6.1 |

Всё это опционально: на старом клиенте недоступное тихо отключается,
а вне Telegram `js/tg.js` подменяет API заглушками поверх `window` и
`localStorage` — тот же `index.html` остаётся обычной веб-страницей.

### Сейв
Сохраняются только `{seed, levelNum, lives}`: генератор детерминирован,
поэтому раскладка любого уровня восстанавливается из seed. Позиция
внутри уровня намеренно не хранится — при возврате уровень начинается
заново. В меню появляется кнопка «ПРОДОЛЖИТЬ»; на GAME OVER и после
прохождения кампании сейв стирается.

Вне Telegram (и на клиентах старше Bot API 6.9) то же самое хранится в
`localStorage` — ключ `sokoban_save`.

### Производительность
Генерация уходит в Web Worker (`js/gen-worker.js`), а следующий уровень
собирается фоном, пока игрок читает оверлей победы, — переход «ДАЛЬШЕ»
получается мгновенным. Без воркера (открытие с диска) генерация идёт в
UI-потоке после отрисовки заставки. Замеры на десктопе: уровень 1 — ~5 мс,
50 — ~48 мс, 100 — ~120 мс; в мобильном WebView примерно ×5.

## Файлы
```
index.html         разметка, HUD, оверлеи, подключение SDK Telegram
css/style.css      ретро-тема, CSS-спрайты, CRT-эффект, компактный режим
js/tg.js           адаптер Telegram Mini Apps (вне Telegram — заглушки)
js/solver.js       A*-решатель по толчкам, мёртвые клетки, детектор тупиков
js/generator.js    планировка комнат, кластер целей, направленный скрэмбл
js/gen-worker.js   генерация уровня в фоновом потоке
js/levelsource.js  выдача уровней: воркер, предгенерация, фолбэк
js/game.js         состояние партии: ходы, толчки, жизни, отмена, сейв
js/render.js       DOM-рендер поля, HUD, оверлеи, тосты
js/main.js         связка: ввод (клавиши/крестовина/свайпы), экраны

.github/workflows/pages.yml  автопубликация на GitHub Pages при пуше в master
.nojekyll                    отключает обработку Jekyll на Pages
```

Порядок подключения скриптов важен:
`tg → solver → generator → levelsource → game → render → main`.

Для отладки `js/main.js` выставляет `Sokoban.app = {game, renderer}` —
игровой логики там нет, только доступ к состоянию из консоли.
